# Decisions

Why FINN is built the way it is. D-entries were decided before the first line of code (they come from CLAUDE.md). S-entries are made while building. Newest at the bottom.

## Decided up front

| # | Area | Decision | Why |
|---|---|---|---|
| D1 | Product | PUSH is a **Morning Brief**: "N things that matter" cards grouped by priority, routine filings collapsed into one row, ending in "You're all caught up". | A finite, scannable brief beats an infinite feed; the user decides in three seconds whether to care. |
| D2 | Product | PULL is a **Promise Tracker** (last 4 quarters: Kept / Partly / Missed / Too early, each with quote, source document and page) plus an "Ask the documents" box. | It tests whether management delivers on what it says, and every claim is traceable. |
| D3 | Product | PULL answers only from annual reports and concall transcripts. No news, broker notes or outside model knowledge. "Not found in the documents" is a valid answer. | Grounding is the point; refusing to guess is a feature. |
| D4 | Product | Mobile-first, bottom nav (Brief, Alerts, Research, Settings), actions in the thumb zone. | Most use will be on a phone. |
| D5 | Product | Nothing is hard-coded to the demo companies; any NSE ticker must work. | Brief requirement. |
| D6 | Architecture | Push data is precomputed by a Python pipeline into static JSON (`frontend/public/data`) and served by Next.js on Vercel. | Instant load, no cold start. |
| D7 | Architecture | The pipeline stores raw metrics (volume ratio, % move); the client applies the user's thresholds. | Changing a threshold updates alerts instantly, with no recompute. |
| D8 | Architecture | FastAPI on Render is used only for PULL on tickers that are not precomputed, and for Ask-the-documents. The free tier sleeps, so the UI shows an honest "waking up research engine" state. | Keeps the backend off the critical path of the main screen. |
| D9 | Architecture | User settings live in localStorage. No accounts, no personal data. | Nothing to protect, nothing to leak. |
| D10 | LLM cost | Tier 0 uses no LLM: classification from BSE category/subcategory plus keyword rules. | Most filings can be classified for free. |
| D11 | LLM cost | Tier 1 (cheap model): one-line summaries, results-number extraction to strict JSON, bio condensing, ambiguous classification. Tier 2 (strong model): promise extraction and the promised-vs-delivered judgement only. | Spend the expensive model only where judgement is needed. |
| D12 | LLM cost | Model names come from env vars only (`LLM_CHEAP_MODEL`, `LLM_STRONG_MODEL`, `LLM_FALLBACK_MODEL`). A 429 triggers backoff, then the fallback provider. | Free-tier models and quotas change; that should not need a code change. |
| D13 | LLM cost | Every LLM output is cached in SQLite under `sha256(doc_bytes + prompt_version + model)`, and every call is logged (provider, model, tokens, estimated cost, cache hit) for `docs/cost.md`. Long PDFs are chunked and only relevant chunks are sent. | The same input never costs twice, and efficiency is graded. |
| D14 | Truth | The LLM never invents numbers. Figures are extracted with their source (document, page); QoQ/YoY deltas and margins are computed in code. | A wrong number in a finance app is worse than a missing one. |
| D15 | Truth | A quote is shown only if it appears verbatim (whitespace-normalised) in the source text. Document text is treated as data; instructions inside it are ignored. | Prevents fabricated quotes and prompt injection. |
| D16 | Truth | Extracted results numbers are cross-checked against an independent source where available (for example yfinance quarterly) and shown with a check or warning badge. | Lets the user see how far to trust a figure. |
| D17 | Truth | If a source fails, show the last cached data with its timestamp. Sample or cached data is always labelled. Never a blank screen, never silent fake data. | A demo that breaks is the worst outcome. |
| D18 | Security | Secrets live only in `.env` (gitignored) and the Vercel/Render dashboards; the frontend never holds a key. `.env.example` has names only. | The repo is public; keys must not leak. |
| D19 | Security | CORS allows only the Vercel domain and localhost; the backend is rate-limited per IP; fresh LLM research is capped per day (cached results are unlimited). | Protects the free quota. |
| D20 | Security | Ticker input must match `^[A-Z0-9&\-]{1,20}$`; outbound fetches go only to an allowlist of domains, with a 25 MB cap and timeouts; debug endpoints need an `ADMIN_TOKEN` header; dependencies are pinned. | Blocks SSRF, abuse and supply-chain drift. |
| D21 | Design | Every card answers "do I need to care?" headline-first. Progressive disclosure runs headline, numbers, source document and page. | The 3-second rule. |
| D22 | Design | Risks, misses and red flags rank above good news, and every pushed item shows why it ranked high. | Negativity bias, plus transparency. |
| D23 | Design | Colour carries meaning only (red bad, green good, amber watch). Money in ₹ Cr, percentages and ▲▼. Groups of at most 5. Smart defaults: 24 h window, 2× volume, ±5% move. | Fast, honest scanning. |
| D24 | Design | The user controls the window, thresholds and categories, and can mute a company. Plain language, one-line "so what", no filler. | Control reduces alert fatigue. |

## Made while building

| # | Step | Decision | Why |
|---|---|---|---|
| S1 | 1 | Config files are objects holding a named list (`{"companies": [...]}`, `{"categories": [...]}`) plus a `description`, not bare arrays. | JSON has no comments, and a wrapper lets us add fields later without breaking readers. |
| S2 | 1 | `size_bucket` is `large`, `mid` or `small`, taken from the lists in STEPS.md. It is a label, not a market-cap lookup. | Used for display and grouping only; the symbols themselves are verified in Step 3. |
| S3 | 1 | Categories have a stable snake_case `id` (`m_and_a` for M&A) and a display `label`. | Safe as keys in code and JSON. |
| S4 | 1 | Routine means insider trading, AGM/EGM, earnings-call logistics, postal ballot and investor meetings. `unclassified` is deliberately not routine: it ranks low but stays visible. | A filing we cannot classify might still matter, so it is never hidden in the collapsed row. |
| S5 | 1 | Alerts default to on only for litigation, pledging, results, management change, M&A, credit rating, fund raise and bonus/split. Nothing routine alerts by default (enforced by a test). | Alert fatigue. The user can switch any category on. |
| S6 | 1 | Category weights are base priorities (litigation 95, pledging 90, results 88, management change 85 and so on). The scorer may adjust per filing, for example a credit downgrade or a large miss. | A category cannot tell good news from bad; the filing can. |
| S7 | 1 | `scripts/check-secrets.sh` is plain bash plus grep. It runs as a pre-commit hook, has an `--all` mode for CI, never prints a match, supports an inline `secret-check:allow` marker, and fails closed if its export of the staged files is incomplete. | It must behave the same in Git Bash on Windows and on a Linux runner, and a scanner that silently says "clean" is worse than none. |
| S8 | 1 | Commits use the repo-local GitHub noreply address, not a personal email. | The repo is public. |
| S9 | 1 | `.gitattributes` forces LF line endings. | Shell scripts with CRLF break on Linux runners and in git hooks. |
| S10 | 2 | Python 3.14 locally and on Render (`PYTHON_VERSION` pinned in `render.yaml`). All dependencies, backend and frontend, are pinned to exact versions. | Render now defaults to 3.14, so local and production match, and builds are repeatable. |
| S11 | 2 | `/health` is exempt from the rate limit; `GET /` carries the default limit. | Render's health check must never be throttled into a restart loop, and the limiter still has a route to be tested on. |
| S12 | 2 | The per-IP limit trusts `X-Forwarded-For` (uvicorn `--forwarded-allow-ips='*'`), which a determined client could spoof. The real guard on the free LLM quota is the global `DAILY_FRESH_RESEARCH_CAP`. | Behind Render's proxy every request would otherwise share one IP. To be re-checked once deployed. |
| S13 | 2 | The status pill has two states beyond the three in the brief: "Checking engine..." for the first 3 seconds and "Engine not configured" when `NEXT_PUBLIC_API_URL` is missing. | A missing setting should be reported as such, not shown as "offline". |
| S14 | 2 | System fonts, no web fonts. | Nothing to download at build or run time, and no layout shift. |
| S15 | 2 | `meta.json` with `"note": "skeleton"` renders a visible "Sample data" tag; a missing file renders "Data unavailable right now". | Sample data is always labelled and failure is never silent (D17). |
| S16 | 2 | Next.js `cacheComponents` and `partialPrefetching`, enabled in the generated config, were switched off. | They change rendering rules and the skeleton does not need them. |
| S17 | 2 | The `LayoutProps` helper type was replaced by an explicit props type. | `LayoutProps` only exists after a build, which broke `tsc` on a fresh checkout. |
| S18 | 3 | The data pipeline runs on the laptop for now, and the JSON it writes is committed. Render and GitHub Actions take over a source only once the probe table shows they can reach it. | Both exchanges are proven only from a home connection, and Indian exchange sites often refuse datacenter IPs. |
| S19 | 3 | BSE is the primary source for announcements and documents. NSE is the fallback and the only source for NSE-only issuers such as CDSL. A ticker resolves to BSE when it has a scrip code, otherwise to NSE. | BSE gives a category and subcategory that rules can use. NSE needs no code mapping but covers what BSE does not. |
| S20 | 3 | Symbols are mapped by ISIN, never by name, and a missing BSE code is `None`, not a guess. | A name search for CDSL returns ICDS Ltd, a different company. |
| S21 | 3 | The BSE client sends all four required headers, makes one request at a time with a 0.25 s pause, and was not load-tested. Spans are split into 365-day windows. | It is someone else's production API, and 365 days is the most it accepts. |
| S22 | 3 | A transcript is a filing whose subcategory says so or whose text says "transcript", and the pipeline looks back 14 months. | Companies file transcripts under different subcategories, and the fourth quarter back can be 13 months old. |
| S23 | 3 | The outbound allow-list covers `nseindia.com` and `nseindia.in`. | NSE serves attachments from both. |
| S24 | 3 | PyMuPDF is pinned to 1.28.x, not 2.x. | 2.x bundles onnxruntime and networkx (about 90 MB more, and a lot of RAM) that a 512 MB free instance cannot spare, and plain text extraction does not need them. |
| S25 | 3 | Annual reports will get their own, larger download cap, streamed to disk, instead of the 25 MB cap used elsewhere. To be settled in Step 9. | A 22 MB report already appears in a three-company sample; bigger groups will exceed 25 MB. |
| S26 | 3 | The `/debug/sources` route and `probes/` are temporary: admin-token only, hidden from the API docs, removed once the Render column is filled. | Useful once, then an unnecessary surface. |
| S27 | 4 | Each company gets announcements from one exchange per run: BSE if it has a scrip code, otherwise NSE, with the other as a fallback if the first fails. Feeds from the two exchanges are not merged. | The exchanges use different IDs and labels, so merging would invent duplicates. One clean source is easier to trust and to explain. |
| S28 | 4 | Percent moves are computed from adjusted closes; the close that is shown is the real traded close. | A split or bonus would otherwise show up as a crash and trigger a false alert. |
| S29 | 4 | The pipeline keeps 14 days of announcements and 3 months of prices per company. One combined `brief.json` carries every portfolio filing plus the last 5 sessions of signals; each company also has its own `<SYMBOL>.json`. | The app offers windows up to 7 days; the extra week is slack. One file means one request for the Brief. |
| S30 | 4 | If a source fails, that part keeps its last good data. The file says which parts are `stale` and since when, and records the `errors`. Files are written atomically. | The brief says never to show a blank screen or lose data silently (D17). |
| S31 | 4 | The BSE client retries a transient 400, 429 or 5xx up to three times with a pause. A 403 is never retried. NSE retries once with a fresh session. | BSE rejected a valid request once in 22 companies and recovered immediately; a block should not be hammered. |
| S32 | 5 | Classification reads the exchange's own label first and uses keywords only for vague labels (BSE "General", NSE "Updates", board-meeting outcomes). When several keyword rules match, the most serious category wins. | A specific label is more reliable than a guess from text, and a risk must never lose to a harmless-sounding word in the same filing. |
| S33 | 5 | Priority is the category weight plus a per-filing adjustment that encodes the negativity bias: a downgrade +14, a key person leaving +12, a pledge invoked +6; a reaffirmation -22, a pledge released -30, a company-secretary change -12. | A category cannot tell good news from bad; the filing can (D22). |
| S34 | 5 | "Routine" belongs to the filing as well as the category: ESOP allotments, newspaper copies, monitoring-agency reports and compliance certificates collapse into the routine row although their categories usually do not. | Keeps the Brief short without hiding categories that sometimes matter. |
| S35 | 5 | Anything the rules cannot place stays `unclassified`, visible at a low priority (35), never hidden as routine. Exchange questions (volume spurt, news verification, clarification) are lifted +15 to +22 and operational disruptions +28. | A filing we cannot classify might still matter. A regulator asking a company to explain itself is information. |
| S36 | 5 | A board-meeting outcome with no readable text stays unclassified: its content is only in the PDF. These are the main candidates for the cheap model once keys exist. | It is the honest limit of Tier 0. |
| S37 | 5 | A results announcement filed twice on BSE (as `Result` and as the board outcome) is shown once, preferring the exchange's own results label; the kept item records how many it absorbed. | Showing both would double-count the most important card. |
| S38 | 5 | Headlines are built by rules (boilerplate removed, case tidied, abbreviations respected, BSE's `?` rupee sign repaired) and are labelled as rule-built. A model-written one-liner may replace them for a few filings later. | Every filing needs a readable line for free; a model call per filing would waste the quota. |
| S39 | 6 | The Brief's time window (24 hours, 3 days, 7 days) is counted back from the data's own timestamp, not from the viewer's clock. | A weekend, a holiday or a stale file still shows its latest day instead of an empty screen, and "Data as of" says how old that is. |
| S40 | 6 | Cards are grouped as "Needs attention" (priority 75 and up) and "Worth a look" (45 to 74), at most five each with the rest one tap away. Lower-priority and routine filings collapse into rows. "N things that matter" counts the first two groups. | The brief asks for three to five key items, not fifty (design rule 2, rule 10). |
| S41 | 6 | Each filing has a `tone` (bad, watch, good or neutral) set by the classifier. The app colours only the tone, and always adds a text tag ("Risk", "Watch", "Good news"). Results stay uncoloured until their numbers are known. | Colour carries meaning only (rule 9), and a colour-blind reader must lose nothing. |
| S42 | 6 | Settings live in localStorage as overrides only; defaults come from `config.json`, which the pipeline publishes from `config/`. Anything unexpected in storage is ignored. | A change of default reaches everyone who never touched that setting, and corrupt storage cannot break the screen. |
| S43 | 6 | A re-appointment of someone already in the role ranks below a new hire (-15, neutral). A key person leaving in the same filing still wins. | HDFC Bank's re-appointment of a whole-time director appeared under "Needs attention", which was noise. |
| S44 | 6 | The frontend's unit tests use vitest, and `@types/node` moved from 20 to 22 to satisfy vitest's peer range. The 7 moderate npm audit findings are all in development tooling; production dependencies have none. | Pure logic (windows, grouping, IST day boundaries, settings validation) is where subtle bugs hide, and it needs no browser to test. |
